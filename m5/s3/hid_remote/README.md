# StickS3 BLE Media Remote — Python prototype

На StickS3 зараз встановлено [нативну C++ прошивку](native/README.md), яку зібрано через PlatformIO. Ця сторінка описує попередній UiFlow/MicroPython варіант.

Застосунок MicroPython для **UiFlow 2.5.2**. Комп'ютер отримує стандартні BLE HID Consumer Control події для медіаклавіш і стандартні BLE HID Keyboard події для стрілок. Потрібне лише спарювання Bluetooth; програма-посередник і перепризначення клавіш не потрібні.

## Керування

| Дія | Результат |
|---|---|
| Синя передня кнопка A, короткий клік, USB-C нахилений вгору | Volume Up |
| Та сама кнопка, USB-C нахилений вниз | Volume Down |
| Один короткий клік у горизонтальному положенні | Play/Pause |
| Та сама кнопка, StickS3 нахилений ліворуч | Клавіша Left Arrow |
| Та сама кнопка, StickS3 нахилений праворуч | Клавіша Right Arrow |
| Утримувати синю кнопку довше 500 мс | Нічого; автоповтору у v1 немає |
| Утримувати бічну програмовану кнопку B 1,5 с | Зупинити пульт, відключити BLE |

Дія визначається після debounce **25 мс** і відпускання кнопки. Напрямок/режим фіксується під час натискання, тому можна швидко робити послідовні кліки гучності без очікування double-click timeout. Гучність змінюється стандартним кроком ОС.

Класифікатор використовує два підписані кути відносно горизонтальної площини. На перевіреному екземплярі USB-C догори/донизу приходить через `ay`, а фізичний крен — через `ax`: додатний `ax` відповідає лівому крену, від'ємний — правому. Якщо обидва кути перевищують поріг, перемагає більший абсолютний кут; для перемикання осі потрібна перевага 8°, щоб режим не тремтів на діагоналі. Фільтр EMA має коефіцієнт 0,25 при циклі близько 20 мс; поріг входу — ±30°, повернення в горизонтальний режим — всередині ±20°. Значення цієї прошивки фактично в g. Нульові або аномальні дані IMU не генерують команду.

Екран показує статус з'єднання, режим, останню команду та батарею. Через 5 секунд без натискань підсвітка вимикається і LCD переходить у power-save; рух або BLE-події його не будять. Перше наступне натискання одночасно будить дисплей і виконує команду. `Connected` означає зашифроване з'єднання з комп'ютером. Стрілки діють у програмі, яка має фокус; у медіаплеєрі вони зазвичай перемотують на налаштований плеєром крок.

На старті застосунок вимикає Wi-Fi STA/AP, Speaker, Mic і LED та пробує знизити частоту CPU до 80 МГц. Кнопки опитуються раз на 20 мс. IMU читається раз на 100 мс у спокої, але негайно і кожен цикл під час натискання; фільтр зберігає попередній час реакції. Батарея читається раз на 60 секунд: нижній рядок показує відсоток і напругу в мВ, а USB-журнал додає стан заряджання. BLE Battery characteristic оновлюється лише після зміни відсотка. Після запуску або disconnect BLE рекламується з інтервалом 100 мс протягом 30 секунд, потім переходить на 500 мс. Deep sleep не використовується, тому BLE залишається доступним.

## Запуск на стіку

Файли встановлюються поверх UiFlow без заміни системної прошивки:

- `/flash/main.py` — малий loader для автоматичного запуску пульта.
- `/flash/main.py.uiflow-backup` — одноразова резервна копія попереднього `main.py`.
- `/flash/apps/hid_remote.py` — копія entry point для ручного запуску.
- `/flash/libs/hid_remote/` — логіка та локальна копія бібліотеки.
- NVS namespace `hidremote`, key `keys` — лише ключі BLE цього застосунку.

Команда `install` використовує штатний boot option UiFlow **Run main.py directly**: після ввімкнення StickS3 одразу запускає M5 Media Remote без USB і без очікування Wi-Fi. Системні файли UiFlow та `/flash/boot.py` не змінюються.

Щоб повернутися до launcher UiFlow, затисніть передню синю кнопку A, коротко натисніть бічний Reset і тримайте кнопку A ще приблизно 0,5 с. UiFlow 2.5.2 збереже режим launcher для наступних стартів. Повернути автозапуск пульта можна командою `device.py app`; команда `device.py menu` переводить у launcher програмно. Не утримуйте Reset: довге натискання вмикає режим прошивання.

На Mac відкрийте **System Settings → Bluetooth** і виберіть пристрій у списку Nearby Devices. У macOS для такого BLE HID-пристрою окрема кнопка `Connect` може не показуватися: підключення починається натисканням на рядок пристрою. У списку також може залишатися закешоване ім'я `MPY ESP32`, успадковане від UiFlow; актуальне ім'я в advertising — `M5 Media Remote`. Перевірте, що на стіку з'явилося `Connected`. Для Play/Pause відкрийте програвач із підтримкою системних медіаклавіш. Стрілки спочатку зручно перевірити в текстовому полі, а потім у медіаплеєрі. Гучність перевіряйте на аудіовиході, який підтримує системне регулювання; деякі цифрові виходи мають фіксовану гучність.

Версія 0.2 додає Keyboard characteristic і змінює HID report map. Якщо всі клавіші вже працюють, звичайне оновлення застосунку **не вимагає** `Forget This Device` або `device.py forget`: ключі BLE зберігаються. При зміні опису HID після старої версії 0.1 чисте спарювання може знадобитись один раз, лише якщо комп'ютер використовує застарілий опис.

Якщо Windows показує `Connected`, а команди не працюють, подивіться на Stick: `PAIRING...` означає, що з'єднання ще не зашифроване; `SUSPENDED` означає команду HID Suspend від комп'ютера; `NO BOND` означає шифрування без записаного peer-ключа; `CONNECTED` означає зашифроване з'єднання зі збереженим peer-ключем. USB-журнал містить `BLE connect`, `BLE bond lookup hit/miss`, `BLE bond update` (лише тип і кількість записів), `BLE encryption`, `BLE suspend/resume`, тип запиту підтвердження та результат запиту pairing. Журнал ніколи не друкує ключі, коди підтвердження чи адреси. Для діагностики можна читати `monitor` безпосередньо на Windows-комп'ютері, підключивши Stick через USB; на Mac під час Windows-тесту варто вимкнути Bluetooth, щоб він не забрав з'єднання.

Під час перевірки Windows 2026-09-21 Stick з'єднався без шифрування, `gap_pair` повернув `EALREADY` (процедура вже тривала), а згодом прийшла невдала подія `encryption (0, 0, 0)`. Після **Remove device** у Windows та нового запиту `Connect to my device` журнал один раз показав `encrypted=1, bonded=1`, але з'єднання знову зірвалося; у NVS після цього залишився тільки локальний запис типу 10, без peer-ключа. Отже, успішний прапорець `bonded` одного сеансу ще не доводить, що reconnect запрацює. `device.py forget` не запускайте: він очистив би весь namespace, включно з іншими хостами. Для наступної перевірки потрібен суцільний журнал від початку чистого pairing до disconnect і запис `bond update` для peer; після reset — робочий reconnect без нового pairing.

Контрольний цикл того ж дня без змін прошивки під час експерименту: після Remove у Windows і нового pairing Windows показала `Connected`, керування працювало, а Stick показав `NO BOND`; журнал мав `encryption (1, 1, 16)`, але не мав `bond update` для peer. Після фізичного вимкнення Windows показала `Paired`; після ввімкнення без ручних дій Windows лишилася `Paired`, Stick показав `Pair via BT` і рекламувався без `BLE connect`. У Windows не було окремої дії Connect для цього вже спареного пристрою. Це підтверджує невдалий автоматичний reconnect саме після живлення; перевірка через `device.py app` не еквівалентна цьому циклу.

Окремий контрольний цикл із дозволеним Legacy Pairing (`le_secure=False`) теж не дав reconnect: після Forget і нового pairing кнопки працювали лише до вимкнення; після ввімкнення Windows залишила `Paired`, коротко мигнула `Connected` і знову повернулася до `Paired`, а кнопки не працювали. У журналі під час сеансу було `encryption (1, 1, 16)` і `NO BOND`, без `bond update` для peer. Після цього експериментальне послаблення безпеки прибрали і на Stick повернули попередній режим `le_secure=True`. Повторювати той самий цикл без іншої конкретної зміни немає сенсу.

Наступна локальна правка виправляє конкретну невідповідність HID Service: для Keyboard Application Collection додано Boot Keyboard Input/Output characteristics, а Protocol Mode тепер дозволяє читання й Write Without Response. Вона не змінює BLE-адресу чи Report Map, але розширює GATT-сервіс, тому наступна перевірка Windows потребує Remove device і нового pairing. Це гіпотеза щодо завершення налаштування HID у Windows, **ще не підтверджене виправлення reconnect**. Після нового pairing критично побачити `bond update` для peer (тип, відмінний від локального IRK 10); лише тоді вимикати Stick і перевіряти повторне підключення.

Перевірка цієї правки на StickS3 2026-09-21: після Remove у Windows сам з'явився `Add device` popup; після підтвердження Windows показала `Connected`, усі перевірені команди працювали. USB-журнал знову показав `encryption (1, 1, 16)` і `STATUS No bond`, без `bond update` для peer. Після вимкнення Windows перейшла в `Paired` приблизно за 12 секунд; після ввімкнення двічі коротко мигнула `Connected`, повернулася в `Paired`, а кнопка не діяла. Отже, Boot Keyboard/Protocol Mode виправляють HID-відповідність, але **не усувають відсутність збереженого peer-ключа й не дають Windows reconnect**. Наступний цикл із тими самими параметрами неінформативний.

Ізольована перевірка `bond_probe.py` 2026-09-21: проба використовує окрему випадкову статичну BLE-адресу, ім'я `M5 Bond Probe`, мінімальний GATT-сервіс без HID і окремий NVS namespace `hidprobe`. Windows показала її в Other devices як `Paired`; USB-журнал показав connect → `encryption 1 1 16` → disconnect, але жодного збереження peer-ключа. Пряме читання NVS після зупинки проби підтвердило тільки тип `[10]`, кількість `1` — локальний IRK. Тобто така сама відсутність peer bond відтворюється **без HID-сервісу**. Це звужує причину до pairing/key distribution між Windows і BLE-стеком цієї збірки UiFlow або налаштувань Windows; не доводить, що дефект саме в MicroPython. Після тесту відновлено автозапуск M5 Media Remote. Повторний тест без зміни механізму pairing не потрібен.

Для перевірки автономності повністю заряджайте Stick, потім від'єднайте USB, залиште BLE підключеним, дайте екрану згаснути й засічіть фактичний час до вимкнення. Перед початком і під час перевірки коротко будіть екран та записуйте мВ поряд із відсотком. Мета — щонайменше 2 години; сама зміна відсотків без виміряного часу не показує автономність. Якщо час лишається меншим, потрібні заміри струму або перехід до нативної прошивки після повної резервної копії флешпам'яті UiFlow.

## Завантаження через USB

Потрібні Python 3 та `pyserial` (на Mac вони вже є в Python PlatformIO). Збірка/прошивання PlatformIO не потрібні. **Не запускайте `pio run -t upload` для цього застосунку.** Порт не повинен бути відкритий у Serial Monitor, Thonny або WebTerminal одночасно. `device.py` сам знаходить один підключений StickS3 за USB VID/PID; якщо автоматичний пошук не спрацює, задайте `--port` перед підкомандою.

### Перенесення експерименту на Windows

Скопіюйте або клонуйте цей репозиторій на Windows. Відкрийте PowerShell у каталозі `m5\s3\hid_remote`, підключіть Stick через USB та виконайте:

```powershell
py -3 -m pip install pyserial
py -3 device.py monitor --seconds 120
```

Вже встановлений на Stick пульт не потребує повторного `upload` чи `install`: `monitor` лише читає USB-журнал і не перезапускає програму. Якщо є кілька serial-портів або автоматичний пошук не знайшов Stick, перегляньте COM-порт у Device Manager та вкажіть його явно:

```powershell
py -3 device.py --port COM5 monitor --seconds 120
```

Після фізичного вимкнення Stick USB-порт зникне й `monitor` завершиться або повідомить про втрату порту — це очікувано; після ввімкнення запустіть команду знову. Для наступного контрольного циклу не змінюйте код, ключі чи pairing посеред перевірки: запишіть окремо початковий статус Windows, перше підключення, статус після вимкнення та після ввімкнення. `M5 Bond Probe` вже показав відсутність peer-ключа і без HID, тому його повторний запуск без зміни механізму pairing не дасть нових даних.

### Mac / розробка

З кореня репозиторію:

```sh
/Users/dmytro/.platformio/penv/bin/python /Users/dmytro/electronics/m5/s3/hid_remote/device.py upload
/Users/dmytro/.platformio/penv/bin/python /Users/dmytro/electronics/m5/s3/hid_remote/device.py run
```

Для постійного автозапуску виконайте:

```sh
/Users/dmytro/.platformio/penv/bin/python /Users/dmytro/electronics/m5/s3/hid_remote/device.py install
```

`install` передає файли через raw REPL на 115200, перевіряє SHA-256, зберігає попередній `main.py`, вмикає штатний режим `Run main.py directly` і перезавантажує StickS3. Повторний `install` не перезаписує резервну копію. `upload` лише оновлює файли застосунку, а `run` запускає його тимчасово. Для явного порту перед підкомандою вкажіть `--port /dev/cu.usbmodemXXXX` на Mac або `--port COM5` на Windows.

Перемикання режиму старту без видалення файлів:

```sh
/Users/dmytro/.platformio/penv/bin/python /Users/dmytro/electronics/m5/s3/hid_remote/device.py app
/Users/dmytro/.platformio/penv/bin/python /Users/dmytro/electronics/m5/s3/hid_remote/device.py menu
```

Команда `run` тримає USB-сеанс відкритим, щоб macOS не скинув StickS3 під час закриття serial-порту. Після pairing і перевірки натисніть `Ctrl-C` у цьому терміналі. Для короткого перегляду стартового журналу можна використати `run --seconds 5`. Після `install` можливий reset від закриття serial-порту безпечний: пульт знову запуститься через `/flash/main.py`.

Читання журналу **без переривання** пульта:

```sh
/Users/dmytro/.platformio/penv/bin/python /Users/dmytro/electronics/m5/s3/hid_remote/device.py monitor --seconds 30
```

Для перевірки фактичної орієнтації осей тимчасово зупиніть `run` через `Ctrl-C` і виконайте:

```sh
/Users/dmytro/.platformio/penv/bin/python /Users/dmytro/electronics/m5/s3/hid_remote/device.py imu --seconds 20
```

Команда друкує `ax`, `ay`, `az` кожні 100 мс. На перевіреному екземплярі рух USB-C вгору/вниз для цього прототипу визначається через `ay`, а попереднє трактування `ax` як керуючої осі виявилося непридатним для реального хвату.

Зупинка / повернення до REPL:

```sh
/Users/dmytro/.platformio/penv/bin/python /Users/dmytro/electronics/m5/s3/hid_remote/device.py stop
```

Тільки якщо свідомо потрібно очистити **всі** ключі пульта в namespace `hidremote` (включно з ключами інших комп'ютерів):

```sh
/Users/dmytro/.platformio/penv/bin/python /Users/dmytro/electronics/m5/s3/hid_remote/device.py forget
```

Після `forget` видаліть **M5 Media Remote** або закешований **MPY ESP32** у Bluetooth на комп'ютері, запустіть `run` і спаріть заново. Для поточної діагностики Windows цю команду **не запускайте**: вона не виправить відсутність peer-ключа в новому pairing. Звичайне вимкнення/увімкнення не має потребувати `forget`. Ключі не друкуються в журналі та не копіюються на комп'ютер.

## Перевірка

```sh
cd /Users/dmytro/electronics/m5/s3/hid_remote
/Users/dmytro/.platformio/penv/bin/python -m unittest -v test_remote.py
```

Автоматичні тести перевіряють усі п'ять положень, діагоналі, гістерезис і перемикання осей, debounce, фіксацію режиму, таймер дисплея, Consumer Control та Keyboard press/release, правильні report handles, очищення після disconnect, перехід advertising 100→500 мс, відкладений pairing fallback, стани `SUSPENDED`/`PAIRING` та частоту читання IMU. BLE-тести використовують підставний транспорт, тому не замінюють перевірку на Mac або Windows.

Підтверджено на підключеному StickS3: MicroPython 1.27.0-dirty від 2026-08-28; IMU BMI270 активний і дає близько 1 g у спокої; `ax > 0` відповідає лівому крену; LCD power-save, Speaker/Mic end, Power LED і Wi-Fi API доступні; найдовший UI-рядок має 127 px і вкладається в дисплей 135 px з відступом 5 px.

Для попередньої версії підтверджено спарювання з macOS, правильний фізичний знак поздовжнього нахилу та три медіадії. Автозапуск перевірено після reset: `/flash/main.py` має SHA-256 локального loader, `boot_option=0`, а BLE advertising знову з'являється без запуску `device.py run`. Показник батареї отримується з M5.Power; фактичний приріст автономності версії 0.2 потребує окремого порівняльного вимірювання.

Джерела: [MicroPythonBLEHID](https://github.com/Heerkog/MicroPythonBLEHID), [StickS3 та схема IMU](https://docs.m5stack.com/en/core/StickS3), [MicroPython Bluetooth API](https://docs.micropython.org/en/latest/library/bluetooth.html). Версія залежності та локальні зміни описані у `vendor/LOCAL_CHANGES.md`; ліцензія GPL-3.0-or-later.
